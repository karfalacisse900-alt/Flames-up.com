Definition
Public engaged = DISTINCT non-author active accounts with at least one qualified read, active + selection, or visible active reply. General and sentence replies use the same existing reply table. Multiple reasons and multiple replies contribute one person. Pass is private and never contributes. Removing + or the last visible reply lowers the total only when no other reason remains. A qualified read remains qualified on later visits.

Qualified reads
The existing detail model publishes contentReady after successful detail data loading. Its SwiftUI task runs only while the detail is visible and the app is active, with no profile/listing destination or covering edit/application sheet. The timer is cancelled on visibility loss. A server-issued read session must be at least five seconds old to qualify; the client waits five continuous foreground seconds after receiving it. Network latency can make this conservatively longer than five seconds from render. New sessions invalidate old tokens. Expired/foreign tokens, unavailable Notes and unauthenticated/banned actors are rejected. Neither feed rendering nor legacy /open calls qualify. Legacy instantaneous-open rows are preserved but not backfilled into qualified reads.

Data/privacy
Additive migration 20261120022807_tea_qualified_engagement.sql depends on the previous reviewed 20261120005350_tea_private_interest_insights.sql. New qualified-read/session tables use RLS and are inaccessible to anon/authenticated roles. Only the authenticated Worker supplies the canonical actor to the service-only RPC. Public payloads expose only engagementCount and a response-order timestamp, never participant identities, pass totals or component counts. Author-only Insights exposes qualifiedReads, activePlus and uniqueRepliers; compatibility aliases preserve old-client decoding.

Delivery/update behavior
The existing feed SQL adds engagementCount to each post in the same response. No per-row count HTTP calls. Interest and acknowledged reply mutations return the authoritative count; the existing account-scoped shared signal model updates feed and detail without reloading the list. Older timestamped responses cannot overwrite newer counts. Cached counters never authorize payments, membership or pickup. Sorting/ranking, Home, Support and checkout are unchanged.
