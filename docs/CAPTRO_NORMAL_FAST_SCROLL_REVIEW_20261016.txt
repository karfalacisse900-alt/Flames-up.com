CONFIRMED CODE-LEVEL WORK, NOT A CONFIRMED EXPLANATION OF THE PHONE SYMPTOM
1. CaptroMediaWriting.swift / MIRAPost.mediaWriting(at:): even posts without
   editor overlays canonicalized and SHA-256-hashed the complete carousel twice
   for a single lookup. Geometry and pause/mute lookups repeated this work.
   Now return immediately for absent overlays and resolve only the requested
   media ID, lazily, when a usable ID-bound overlay requires it. Canonical ID
   bytes, legacy index fallback, first-match precedence and per-slide ownership
   are unchanged. Binding already-bound overlays no longer hashes them again.
2. CaptroFeedMediaPager.swift / feedStamp: onGeometryChange wrote a measured
   collapsedHeight into observed row state although production layout never
   read it. Removed that redundant measurement/publication path. Retained the
   row-local store, selection, pause/mute choices and actual stamp layout.
3. CaptroFeedPostView.swift: an unselected/new row previously hashed every media
   ID to search for an empty selection. It now returns the same initial index
   without that work. Selected media still uses stable identity, not positions.
4. CaptroPostMediaGeometry.swift reuses the first-slide writing lookup rather
   than repeatedly resolving the same overlay. No ratio or crop rules changed.

PERFORMANCE METHOD
CaptroPerformance is Release -O with CAPTRO_PERFORMANCE_REVIEW, without DEBUG.
That compile flag is absent from the normal TestFlight archive; diagnostics and
isolated fixture routes do not ship. Diagnostic bundle version is 1.0.1 (2),
identified by workflow run and exact source, not a distributed TestFlight build.
48 deterministic mixed posts, 12-item pages, a delayed failure/retry at offset
36, and a held final empty page. Gesture schedule: 650 pt/s normal drags and
2400 pt/s flicks, short diagonal starts, up/down direction changes, and repeated
passes over cached content. Native drag/release is used, never setContentOffset.
The 50-drag measurement body runs once as XCTest warm-up and once as the measured
iteration: 100 drags per transport. First-pass snapshots include cold visits;
XCTest CPU/memory summaries describe the later measured (warmed) pass. Those are
single samples, not statistically established device performance improvements.
Simulator hardware CPU-cycle/instruction metrics reporting zero are unavailable
counters, not evidence of zero CPU work.
Good fixture transport: 20 ms latency, 2,048,000 bytes/s per request.
Weak fixture transport: 500 ms latency, 64,000 bytes/s per request.
These are per-request URLProtocol conditions, NOT aggregate network conditioning,
packet loss, or real cellular/Wi-Fi. Photos are synthetic local fixture content;
video is local and shared, not a live adaptive-HLS/network benchmark.
Both recordings use the same ordered corpus and gesture schedule, not a matched
physical finger trajectory. Native deceleration can finish at different offsets;
the final screenshots are not a same-post visual comparison. The complete run
recordings and per-phase attachments are retained rather than presenting one
still image as evidence of smoothness.
XCTest waits for quiescence: these discrete gestures do not verify a continuous
finger-down reversal or a touch interrupting real-device deceleration.
Collect CADisplayLink cadence only during motion, offset commands, mounted row
geometry, pagination state, request budgets, aggregate main-thread operation
durations and XCTest CPU/memory/scroll metrics. Serialization happens on explicit
test reads. Timing hooks are excluded from ordinary production hot paths.
