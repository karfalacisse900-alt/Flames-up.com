Changes and reasons
- PostDetailNativeView: empty navigation title instead of Post; removed only the
  Comments/count heading. Actual comments, input, replies and moderation remain.
  Removed Like/Unlike, Share and Organize entries from its three-dot menu. Other
  existing applicable actions are retained; no underlying like/share service
  was removed. Save menu now reads the same account-scoped Favorites store as Home.
- CaptroFavoriteButton: while a request is pending, consume the button's touch
  area and reject new actions instead of disabling hit testing (which could
  send a second tap through to the media). Tap still requires long-press failure;
  scroll movement cancels the press. Accessible organize action is retained.
- CaptroFavoritesStore: retain a single per-post busy reservation across the
  read/write boundary; existing private save, revision, operation-ID retry,
  rollback, collection memberships, Undo and account-generation checks retained.
  Concise failed-write message replaces raw server error text. No like changes.
- CaptroVideoControls: one small shared pair of independent 44pt controls, with
  high-contrast backing, labels and 12pt top-left inset on Home and Details.
  Home playback preferences stay in the existing row-local media-ID state.
- CaptroFeedMediaPager: removed creator-only overlay from bare media. Written
  captions/meaningful stamps remain. Tapping media opens Details; dedicated
  video buttons control pause/mute. Creator stays available in Details. No feed
  dimensions, selection identity, restoration, or preload policy were changed.
- CaptroWelcomeView: normal Dynamic Type uses a measured fixed Layout, not a
  vertical ScrollView. Controls retain intrinsic readable sizes; remaining
  height goes to proportionally fitted approved artwork. Compact spacing on
  short screens. Only artwork performs the existing one-shot reveal/slow zoom.
  Safe-area paper backing and native control accessibility IDs are preserved.

Accessibility conflict
At accessibility text sizes all required authentication/legal actions cannot
fit on one phone-height page without hiding content or shrinking chosen text.
The explicit accessibility-only fallback remains scrollable. Normal text sizes
have no welcome scroll container. This exception is intentional and disclosed,
not a claim that every enlarged layout fits on a single stationary page.

Artwork
Unchanged approved 870x932 hero extraction from the supplied 870x1808 image.
No redraw, image generation, upscaling export, or altered stamp lettering.
It remains provisional: the previous 480pt maximum / 3x / 1.03 zoom envelope
needs at least 1484x1589 source pixels. This update does not resolve source
sharpness or claim physical-device artwork approval.

or evidence of camera quality. Save/comment requests use a controlled local
URLProtocol, not real users. Runtime captures are implementation screenshots,
not generated mockups. No physical iPhone is available on this Windows host.
