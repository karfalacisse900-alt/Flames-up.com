Confirmed code / isolated reproductions
1. Publish callback ignored the canonical POST result. Home performed background
   reconciliation, which intentionally preserves existing order and excludes new
   IDs into an unused pending list. New eligible publications therefore did not
   appear in an already-loaded Home session. A background refresh was not an
   appropriate publication integration path.
   Files: NotificationLibrarySearchCreateViews.swift, MainFeedView.swift.
   Fix: one account-scoped server receipt; fresh scoped eligibility read; insert
   only at idle top; elsewhere keep current order and offer View post. No fake
   post, access bypass, one-item feed replacement or scroll command. Older reads
   cannot overwrite publication state; API read-after-write bypasses both cached
   responses and an older in-flight GET. Preserve server cursor on local insert.

2. Backend offset applied to raw rows while clients advanced by visible rows.
   Visibility filtering repeated IDs and could return an empty page before later
   eligible records. Isolated actual-handler tests reproduced both outcomes.
   Files: backend-cf/src/index.ts, backend-cf/src/feed-pagination.ts.
   Fix: opt-in encrypted account/feed/city-bound keyset cursor with snapshot and
   expiry. Authorization still applies to every page. Empty-with-continuation is
   not exhaustion. Old array clients are unchanged. No schema/data migration.
   Expired cursor requires explicit Refresh feed; no automatic reading reset.
   Real create mapping sets both timestamps; newly published posts sort ahead
   of older migrated posts. A null legacy timestamp is a compatibility edge and
   sorts last under the unchanged ordering; it is not the normal publish path.

3. Viewport sample traversed every loaded ID on scroll/content-size callbacks.
   Fix: cache order indices when order changes; inspect registered mounted cells
   on scroll. Preserve active-post hysteresis and all restoration guards.
   File: CaptroFeedViewport.swift. This removes loaded-count-dependent work but
   alone does not establish the cause of visible physical-device shaking.

4. Four-image prefetch limit was per invocation, not shared across rows/feed.
   A separate prefetch set also dropped secondary ownership of shared work.
   Fix: shared six-job budget, maximum two speculative jobs; visible promotion;
   permit held through real completion; per-reader cancellation and deduplication.
   Existing off-main decoding and bounded caches remain. No claim that decoding
   was previously on-main. Files: MIRAComponents.swift, MIRAImageLoadAdmission.swift.
   A successful delayed image retry failed to set loadedScope, leaving its
   successfully loaded image behind the placeholder; retry now retains identity.

5. Conditional footer disappeared on exhaustion, shrinking native content extent.
   Fix: stable measured footer across loading/retry/end states, including Dynamic
   Type. No repeated content-offset corrections. Runtime comparison must decide
   whether this reproduced a bottom-of-feed clamp in the exercised interaction.
   File: CaptroFeedPaginationFooter.swift, MainFeedView.swift.

6. Delayed cache writes could acquire the next account's cache namespace.
   Feed writes now pin expected account scope before suspension; old work is
   rejected rather than persisted under another account.
   Files: MIRAAppCacheStore.swift, MIRAPerformance.swift, MainFeedView.swift.
