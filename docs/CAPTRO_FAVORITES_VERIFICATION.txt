PRIVATE FAVORITES — implementation / release verification

Scope
Small frosted star on Home media; tap saves the entire post. Long press opens
the real collection picker and cannot also trigger the tap recognizer.
Me has a Favorites destination. Details reuses the same account-scoped store.
Likes, media geometry, stamps, navigation and CaptroFeedViewport are unchanged.
This does not claim to resolve the previously reported device shaking/freezes.

Storage / authorization
app_post_interactions(kind=save) remains the canonical save record. Three
additive private tables hold collections, memberships and mutation revisions.
No original posts, votes, media or existing saves are migrated destructively.
The Worker derives owner identity from authentication. New tables and RPC have
no anon/authenticated grants, RLS enabled, and service-role-only access through
authenticated Worker routes. Existing post visibility filtering gates content
and preview reads; saving does not issue memberships/tickets or change access.
Transactions serialize changes per account. Revision checks reject stale edits;
request IDs avoid duplicate writes on uncertain retries. Unsave clears all
memberships; Undo restores their previous IDs. Deleting a collection preserves
canonical saves. Existing bookmark/library routes use the same transaction.

Native behavior
Optimistic star state, light haptic, non-layout-changing confirmation overlay.
One shared account-scoped store rejects obsolete reads/writes after mutations
or account changes, rolls back failed writes, and exposes Retry/Reload.
Opening/canceling a picker makes no save mutation. Collection selections commit
on Done. Empty selections still keep the post in main Favorites. The collection
list supports create/rename/delete and unavailable saved posts can be removed.
No private Favorites cache persists across logout. The server keeps saves.
