Resolution caveat (OPEN — final artwork approval pending)
Maximum artwork layout width: 480pt. At 3x and 1.03x zoom the required source is
ceil(480*3*1.03) x ceil(480*932/870*3*1.03) = 1484 x 1589 pixels.
At 440pt the required source width is 1360px, not merely 1320px.
The provided 870px-wide image is insufficient for genuine 3x detail. An exported
image with more pixels would not recover real detail. The image stays provisional
until a higher-resolution original is supplied or a new rendition is approved.
Physical-device sharpness has not been checked on this Windows host.

Native implementation
CaptroWelcomeView.swift: welcome-only palette/layout, native exact copy, provider
actions, legal NavigationLinks, dynamic text and scrolling for smaller screens.
Single artwork reveal: 600ms, then 8s ease-in/out scale from 1 to 1.03, no repeat.
Only artwork is animated; controls are immediately enabled unless auth is busy.
Reduce Motion displays a still image immediately. Return from an auth/legal
presentation settles the same retained artwork state rather than replaying it.
Collage is decorative/accessibility-hidden. Native text and buttons remain
accessible. All action/link targets are at least 44pt vertically.

AuthNativeView.swift: uses existing Google and Apple handlers, nonce creation,
backend exchanges, cancellation handling and error reporting. No success is
fabricated. Guest uses existing continueAsGuest(), clearing credentials and
retaining existing authenticated-route restrictions. No permissions were changed.
Existing age/terms/community-guideline consent is not silently accepted or removed:
first provider tap opens a compact consent sheet, then the native provider flow.
Existing email login, registration and password recovery remain accessible via
'Use email instead' in that sheet and the provider-button context/accessibility
action. The approved initial screen gets no additional visible button or section.
Existing legal screens are reused. No changes to legal copy or policies.
