Confirmed causes and repairs
1. Surfaces: appBackground was warm cream; chat had separate header, canvas,
   composer and bubble colors. Use shared adaptive white/black canvas tokens,
   neutral secondary surfaces, readable text and existing forest/onPrimary.
   Remove redundant generic chat subtitle; use scalable header/timestamp fonts,
   44-point attachment targets and an explicitly readable message prompt.
   Root stops using the launch background once the launch overlay is gone.
   A shared navigation-surface modifier sets the adaptive background and bar
   color scheme together, preventing dark status text on dark headers.
   Welcome artwork, launch colors and camera chrome remain unchanged.

2. Tea: every details view began empty and fetched on entry. Add a bounded,
   memory-only store owned by the existing API client: 24 snapshots, 60-second
   freshness, 10-minute presentation retention. Scope includes account and
   session generation. Coalesce concurrent reads, reject wrong destinations and
   obsolete completions, retain successful data on transport failure, and evict
   on 401/403/404/410. Relevant mutation attempts invalidate before/after their
   request, including ambiguous failures; blocking and DELETE requests discard
   affected presentation data, profile/privacy edits require revalidation,
   and logout/account changes clear the old scope.
   Fresh reopen hydrates synchronously; stale refresh keeps content and action
   selection. First load uses the tapped real row as its header. Retry remains
   available after a failed load. Categories now color only compact icons;
   details lead with the entity name and group facts in one neutral section.
   App-hosted testing showed the short details ScrollView did not invoke its
   refresh handler. Details now uses a native refresh-capable List with one
   unstyled row, zero list insets and plain buttons. It preserves the facts'
   layout without changing Home's scrolling, delegates or gesture physics.
   Cached display data does not authorize commerce. Existing server-side
   checkout/join availability checks and payment flow are unchanged.

3. Messages: two view tasks both requested initial data; load also performed
   redundant recent sync and presence work. One polling path now owns initial
   loading before realtime starts. Preserve recent messages on return/refresh,
   skip immediate duplicate load within five seconds, retain existing live
   updates and merge order. A failed first load has an explicit Retry rather
   than looking like an empty chat. Inbox treats a successful empty response as
   fresh and supports forced pull-to-refresh.

4. Other screens: profile entry uses existing revalidation; visitor profile,
   notifications and Settings guard freshness and account scope. Discover
   separates failed reads from empty success and guards old category/cache
   completions. A terminal profile identity error no longer displays a spinner.
   Notifications omit missing optional body text and retired gift copy. Story
   review, Create, media-writing and document surfaces use adaptive theme colors.
   Unknown attendee counts are omitted rather than displayed as zero. Avatar
   borders and verification controls retain readable dark-mode contrast. Existing
   active screens and sheets generally already consume these shared tokens;
   this patch does not replace their navigation or working features.

  -resultBundlePath "$RUNNER_TEMP/Polish.xcresult" \

Remaining acceptance limits
No physical iPhone is connected to this Windows workspace. Simulator snapshots
and isolated delayed/offline transports do not establish physical scrolling
performance, hardware keyboard behavior, real network reconnect or production
chat delivery. Real-device VoiceOver, Reduce Motion, interrupted gestures and
120-Hz scrolling remain device checks. The simulator suite is targeted, not a
claim that every sheet and every production state was manually inspected.
Live creator payments, provider onboarding and backend behavior were untouched
and were not tested as part of this native polish task.
