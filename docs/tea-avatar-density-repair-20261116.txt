Confirmed causes:
- Tea RPC projections exposed author id/name/username, not the avatar URL. The
  native author type also lacked that field, so list/reply/club avatars always
  displayed initials even when the account had a photo.
- The title/count ViewThatFits layout could retain an intrinsic-width title row
  that constrained the entire body column. This wasted the space below counts.
- Access invalidation cleared the conversation list and set a retry message but
  neither reset the old loading flag nor initiated a replacement read. This could
  display Loading Tea alongside Retry. The screenshot does not identify the exact
  account/access event that triggered it on that physical phone.

Changes:
- One bounded, deduplicated lookup of id/avatar_url/metadata for authors ALREADY
  authorized by the Tea RPC. Only photoURL is added to the author response. No
  user-row exposure, per-row profile calls, migration, new downloader or public cache.
- Optional photoURL decoded by native model and passed to existing RemoteAvatar
  in conversation rows, details, replies and club messages. Initials only if absent.
- Full-width preview beneath the title/reply count; 48pt avatars, 16pt preview,
  compact metadata; Tea cue after the label; scaled compact filters; redundant
  Conversations section label removed. Other screens/navigation unchanged.
- Invalidation cancels the obsolete presentation request and starts a fresh read
  while active; tokens prevent old responses/cleanup from overwriting the new load.
  A loading indicator is never shown alongside a failure message.
- The retained, inactive activity list no longer creates its initial loading/error
  status while Conversations is selected. It stays mounted for scroll restoration.
- Screenshot inspection caught the two-line brand exceeding the navigation bar
  at accessibility text sizes. Only that brand is capped at xLarge; conversation
  content retains full Dynamic Type. A new <=44pt header assertion prevents it.
