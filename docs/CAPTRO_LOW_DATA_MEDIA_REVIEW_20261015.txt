CONFIRMED OBSERVATIONS AND TARGETED CHANGES
1. Cloudflare delivery fields were identical for 29 photos in a 12-post public
   sample. Further measurement showed that the existing public variant already
   uses scale-down, width 1366, height 768, metadata none. It is NOT correct to
   claim every current feed photo downloads the full stored original.
   Added two versioned uncropped variants: captroPreviewV1 (480x854 bound),
   captroFeedV1 (1080x1920 bound). Both honor requireSignedURLs. Kept existing
   normal feed URLs because activating 1080 on these portraits would INCREASE
   bytes. The deployed API supplies the smaller thumbnail/preview URL. The
   1080 variant is configured/tested but is not the default delivery override.
   backend-cf/src/image-delivery.ts, src/index.ts,
   tests/image-delivery.test.mjs, scripts/configure-image-variants.mjs.

2. The native renderer previously declined hosted-image derivatives because
   their crop policy was not verified. It now accepts only the exact source or
   verified uncropped derivatives of the same asset/account, including the two
   versioned variants above. It never removes a signature or invents an unsigned
   URL. Partial derivative arrays cannot shift onto a different carousel slide.
   Original geometry, stable media identity, and originals remain unchanged.
   Services/MIRAMediaNetworkPolicy.swift; Components/CaptroPostMediaView.swift;
   Screens/CaptroFeedMediaPager.swift; Screens/MainFeedView.swift;
   Screens/PostDetailNativeView.swift.

3. Existing video readiness code waited about eight seconds, then discarded and
   retried a still-preparing AVPlayer item. This is a concrete slow-startup defect,
   not proof of the reported vertical-scroll cause. Replaced the deadline with
   cancellable readiness observation scoped to the current item/view. Native
   stall avoidance is enabled; removed forced immediate playback and forced
   sub-second buffering. Stale offscreen remote poster extraction is not started
   per mounted idle video. Existing supplied video posters remain supported.
   Components/MIRAComponents.swift; Services/MIRAPlaybackCoordinator.swift.

4. Added a small Data Saver preference and respect actual NWPath.isConstrained,
   without assuming cellular is slow or Wi-Fi is fast. Reduced mode uses the
   smaller preview when safe, bounded image admission (3), no speculative image
   prefetch or prepared players, and lower AVPlayer preferred bitrate/resolution.
   Normal mode retains the global 6-image/2-prefetch budget. Memory pressure
   stops speculation. Shared visible readers retain ownership of a shared load.
   Image decoding was already off-main; it was not reintroduced as a new fix.
   Reduced 18 automatic image retries to two and added a local retry affordance.
   Existing account-scoped memory/disk caching retained. No Nuke dependency added.
   Services/MIRAMediaNetworkPolicy.swift; Services/MIRAImageLoadAdmission.swift;
   Components/MIRAComponents.swift; Screens/SettingsNativeView.swift.

5. HLS already exists. Two public live manifests returned four resolutions from
   320x240 to 960x720, average bitrate approximately 455kbps to 1.16Mbps. No new
   streaming service or transcoding configuration was installed. These samples
   do not prove every historical video has an adaptive ladder. Startup/rebuffer
   improvements are not yet measured on a physical phone.
