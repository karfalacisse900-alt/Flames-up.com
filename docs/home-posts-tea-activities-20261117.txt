Implemented
- Home server reads (For You, Following, Around, guest world board and nearby compatibility route) exclude structured types and records owning purchasables/post objects before the query limit/offset. Video and carousel posts remain eligible. Caption/title keywords are never used.
- Native Home applies the same identity rule on every model mutation, including restored caches, refresh, pagination and older backend responses. Existing records remain in the data/cache layer; failed ordinary media keeps its retry frame.
- Tea's existing activity area uses one Create button. It checks the existing creation-capabilities endpoint, offers the supported Club, Event, Meetup and Deal types, and opens the existing form directly. Conversations retain their separate Post composer.
- The existing /posts activity creation pipeline still creates the canonical structured record and its existing commerce/membership relationships. A confirmed activity does not emit the Home publication receipt. The creator opens its existing authorized Details route within Tea and discovery refreshes with server visibility checks. Private listings are never optimistically inserted in public discovery.
- Home's Add menu no longer contains activity type choices. Reopening an activity type selector stays in its existing form and cannot switch that draft into a Home post. Media capture/import, framing, captions, review and ordinary publishing are unchanged.
- Separate account-scoped draft slots preserve ordinary posts and each activity type. Legacy structured drafts move to Tea without deleting their media. Cleanup retains media referenced by any remaining draft.
- Tea can include legacy structured posts without purchase records, including general-typed records linked to a server-owned event object, using an anti-join to avoid duplicate entries. These rows reuse the original authorized post Details route. Opt-in include_posts=1 preserves the response contract for older clients; cursors are bound to the source selection.
