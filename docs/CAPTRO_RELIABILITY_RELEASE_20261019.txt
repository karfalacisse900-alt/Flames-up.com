CONFIRMED CAUSES / TARGETED CHANGES
1. Payment lifecycle: old clock-only hosted expiry and exact-start booking locks
   were still live. Matching existing repairs use provider-aware reconciliation,
   shared interval capacity, approval/checkout date checks and durable recovery.
   Fair leased scheduling progresses past unresolved oldest-40 batches. Recovery
   records are NOT final resolution. Fulfillment/refund operator mutations remain
   disabled until separately approved; existing paid records are not rewritten.
2. Currency: native pickers exposed currencies beyond reviewed settlement. New
   paid creation is USD-only on both sides. Historical JPY formatting remains;
   no price or immutable purchase snapshot was rescaled. Unreviewed booking
   capacity stays NULL; new bookings require explicit capacity review.
3. Account deletion: old code could swallow cleanup errors then claim completion.
   Prepared leases/checkpoints retain Auth identity until required cleanup finishes;
   failures retry, phone fields scrub only at verified completion. HOWEVER legacy
   D1/R2 inventory and financial-retention manifest are incomplete. Automatic
   destructive cleanup is deliberately disabled. Pending is not completed.
4. Admin dashboard/session refresh: previously prepared canonical metadata-status
   query, independent card errors and typed transient-refresh failures are included
   in the coordinated Worker. Client role claims remain untrusted; security and
   push RPC boundaries preserved. No public signup or permissive policy added.
5. Video: AVPlayerItem.readyToPlay was used as frame presentation. The adapter now
   observes AVPlayerLayer.isReadyForDisplay with player/item/generation checks;
   poster remains until that signal and the first-frame metric moves there.
   Synchronous audio activation/player-preparation lead remains OPEN; no hardware
   cause or hitch improvement has been established by these changes.
6. Image recovery: preserved repaired fallback/cancellation/cache infrastructure.
   Actual CaptroFeedPostView and PostDetailNativeView run in an isolated host:
   corrupt image -> tappable Retry -> expected decoded red fixture pixels;
   no Details opening from Retry and media Y/height unchanged within 1 point.
   Server fallback test also asserts decoded pixels. This is a real app-hosted
   component test, NOT the affected customer's post, full-feed network trace,
   production photograph or proof of physical scrolling smoothness.
7. Upload telemetry: bounded queue (16 waiting/one active; stale jobs discarded)
   captures account/session context. Successful/failed uploads no longer wait for
   telemetry HTTP completion. No new analytics SDK or unbounded background queue.
8. Notifications: typed post/profile/direct/group destinations; relative time;
   mark one opened notification read instead of clearing on inbox load. Unknown
   destinations show a notice. API retains old explicit bulk-read compatibility.
9. Chat: persist a stable send ID before network submission. Server derives a
   sender/thread-scoped canonical ID, inserts once and reconciles ambiguous writes.
   Local failed bubble reconciles with server acceptance, including realtime racing
   POST. Hide-for-me tombstones survive refresh/relaunch, scoped per account/thread.
   Missing local retry media cannot become an empty successful send. APNs delivery
   and exactly-once notification delivery remain outside this acceptance claim.
10. Drafts/Story: missing attachment count blocks accidental altered publication;
   original manifest retained until explicit removal. Retry/keep draft available.
   Story Back retains capture for return from camera. Full per-attachment recovery,
   corrupt-file validation, and persistent Story close/relaunch recovery remain open.
11. Tag People: temporary selection commits on Done only; errors differ from no
   results; cancelled/stale searches do not replace new results; limit announced.
12. Capabilities: independent loading/error/retry without silently treating an
   unknown capability as denial or granting unverified posting permissions.
13. Profile: existing authorized content retained during transient refresh error;
   confirmed access loss clears it; follow requests page beyond filtered first 30;
   removed pin invalidated locally; messaging fetches the real current account ID.
   Dedicated Plans pagination, canonical HTTPS sharing and own-ID visitor edge
   acceptance remain open. Current native design and management destinations kept.
14. Stamps/comments: unavailable status independent of truncated metadata; duplicate
   profile status removed; semantic comment fonts and 44-point button-label targets.
   Broader VoiceOver/Dynamic Type matrix is not certified by source changes alone.
