PASS 1 - TEA AND PRESENTATION REUSE
- Tea conversations retain the real list title/caption while missing data loads.
  Post/reply/author reads start concurrently. Fresh post data no longer prevents
  retrying failed replies. Fresh reopen avoids repeat reads. Explicit refresh works.
- Revalidate displayed general and sentence reply pages before replacing them,
  preserving drafts and expanded targets. Pagination refresh is bounded at 16
  cursors; incomplete/error results leave the previous successful display intact.
- Tea list snapshots retain cursor/data and viewport within the existing API's
  account scope. Details reuse the existing 60-second cache / 10-minute retention.
- A confirmed nonmember club result clears private member data immediately, but
  reuses that denial for 15 seconds. It can open the existing public visitor details
  without rebuilding a failed member request on every visit. Force refresh still
  rechecks access. It grants no club access and changes no join/payment behavior.
- API-owned chat/profile presentation reuse is bounded to 12 heavy models each.
  Up to 64 lightweight unsent chat drafts are retained on eviction. Profile tab and
  viewport selection are retained. Auth/account changes clear retained models and
  drafts; scope checks reject late completions. Blocking/privacy changes invalidate
  presentation. Writes mark profile freshness stale, including ambiguous responses.
  Restricted profile introductions also receive a freshness timestamp without
  querying private posts; pagination denial clears previously authorized content.
- Existing account-scoped disk cache and authorization policy remain in place;
  no global cache purge, second downloader or credentials change was introduced.
- Existing compact Tea author/avatar/follow+, sentence replies, small domain links,
  general replies and pinned composer remain. No author-update UI was reintroduced.

PASS 2 - HOME / MEDIA / WELCOME
- Filter media-eligible Home posts and derive stable IDs once per posts mutation.
  Body updates from scrolling, overlays and playback reuse that result. Stored
  text/structured records and raw pagination remain intact; no deletion or reorder.
- Failed Home refresh keeps content and offers Retry in the existing stable-height
  footer. It distinguishes offline from first-load failure. Retry preserves order.
- Post ratios, sharp edges, carousel identity/selection, media recovery, player
  admission, preview decoding, prefetch budgets and feed physics are unchanged.
  Existing single-video ownership and background/navigation pause remain in place.
- Replace the obsolete welcome collage/8-second zoom with the supplied fitted
  Captro lockup and shared white/dark canvas. Static launch background matches.
  Native sign-in, consent, guest, email, legal and error actions remain available.
  No new launch wait or animation was added. The existing root startup coordinator
  and essential concurrent initialization remain unchanged.
- No Instruments trace is available to attribute the user's Home hitch to this
  derived-data work. The patch removes observable source-level repeated work;
  it does not establish a device frame-rate improvement.

PASS 3 - CHAT / SHARED PRESENTATION
- Lifecycle/URL cancellation is no longer classified as reconnect failure.
- Persistent errors need >=2 failures spanning >=8 seconds before header status.
  The existing subtitle line holds the status/Retry, preserving the message frame.
  No extra reconnect row or red transport banner is inserted above the composer.
- API polling backs off (bounded at 60 seconds), even if the socket looks connected.
  Initial socket join failures retry a bounded five times; existing authorized
  cursor polling remains the fallback. Reconnect never authorizes access itself.
- Equal message snapshots no longer rewrite the list/disk cache or restart the same
  media prefetch. Prefetch is capped by the existing helper and obsolete work cancels.
- Direct/profile/inbox routes reuse the same scoped chat presentation. Drafts and
  viewport survive ordinary navigation/reconnect. Initial chat keeps native bottom
  anchoring; saved visits restore their previous viewport. No keyboard autofocus.
- Sending/Sent/Failed remain server-acknowledgment driven. Failed retry retains the
  existing client request ID. A stale Retry control cannot resend an acknowledged
  row. Existing server idempotency remains unchanged.
- Shared adaptive surfaces already cover Tea/Home/inbox/chat/profile/Scan/settings;
  this pass reuses them for welcome and errors. No active Coming soon sections were
  found in the reviewed screens. DEBUG/sample screens remain isolated, not deleted.
